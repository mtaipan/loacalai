# Аудит Local Gemma Studio как продукта

Дата: 1 ноября 2026. Проверялась рабочая копия `A:\LocalGemmaStudio`, версия исходников 0.16.0.

Это проверка сквозных сценариев, существующих функций, архитектуры и недостающих механизмов. Старый `REVIEW-2026-11-01.md` использовался как список гипотез, а не как подтверждение исправности. Функциональный код в рамках этого аудита не исправлялся.

**Найдено 20 замечаний: 11 воспроизведены на настоящем сервере/в Edge с управляемыми ответами inference, ещё 9 установлены по коду.** Отдельно перечислены недостающие части продукта. Это не сертификат отсутствия других багов: нативные macOS/GPU/микрофон и качество реальных моделей этим прогоном не проверены.

Основной системный дефект — раздельные, несогласованные представления состояния: `state` интерфейса, `Conversation.messages`, `Conversation.history`, `App.runs`, процессы инструментов и состояние скачивания. Успех обычного прохода не означает, что работают повтор, ошибка, смена режима, перезагрузка или остановка.

Дополнение по сообщениям пользователя: необходим выбор режима прав вместо повторного «Разрешить один раз» для каждого файла; на macOS не работает обычная вставка ⌘V и перенос выделения через ⌘⇧T. Первое подтверждено устройством текущего UI/API; macOS-проблемы сообщены пользователем и требуют нативного воспроизведения. Эти требования, проверяемые гипотезы и полный накопленный объём собраны в [DEVELOPMENT-PLAN.md](DEVELOPMENT-PLAN.md). Сейчас идёт сбор плана; реализация ожидает отдельной команды пользователя.

## Критичные сценарии

### 01. P1 — дочерний процесс продолжает работу после сообщения о тайм-ауте

**Воспроизведено на Windows.** Источник: [src/tools.rs:250](A:/LocalGemmaStudio/src/tools.rs:250), [src/executions.rs:33](A:/LocalGemmaStudio/src/executions.rs:33).

Команда запускает короткоживущего родителя, тот запускает потомка с унаследованными stdout/stderr и завершается. `capture` получает завершение родителя и переходит к ожиданию потоков. При тайм-ауте этой ветки лишь прерываются читатели; потомок не останавливается. В тесте инструмент вернул `timed_out` примерно через секунду, контрольного файла ещё не было; через четыре секунды файл уже существовал.

Это затрагивает сборки, скрипты, OCR и другие цепочки процессов. На Unix дополнительно нет группового завершения даже в основной ветке отмены: вызывается `child.kill()` для одного процесса. Последнее установлено по коду, на macOS не воспроизводилось.

**Исправлять механизм:** Windows Job Object / группа процессов на Unix, владение всем деревом до закрытия потоков, единый финализатор остановки. Отдельные случаи: живой родитель, завершившийся родитель, тайм-аут, отмена, закрытие приложения.

### 18. P2 — поздний результат голосового ввода может попасть в новый сеанс диалога

**Установлено по коду; реальный микрофон не использовался.** Источник: [web/app.js:299](A:/LocalGemmaStudio/web/app.js:299), [web/app.js:301](A:/LocalGemmaStudio/web/app.js:301), [web/app.js:305](A:/LocalGemmaStudio/web/app.js:305).

У голосового окна нет поколения/ID сеанса, в отличие от `documentState.session`. После закрытия окна во время распознавания оно продолжает менять глобальные DOM-элементы через `voiceResult`. Если пользователь снова открыл окно, старый результат может изменить его содержимое. Аналогично нет проверки, что окно ещё актуально после ожидающего `getUserMedia`.

**Исправлять:** сеанс и отмена с начала запроса доступа до результата; отбрасывание поздних ответов; явные состояния записи и распознавания.

### 19. P2 — замена существующего файла теряет execute permissions на Unix

**Установлено по коду, на macOS не запускалось.** Источник: [src/changes.rs:63](A:/LocalGemmaStudio/src/changes.rs:63), [src/changes.rs:98](A:/LocalGemmaStudio/src/changes.rs:98).

Новый временный файл создаётся с обычными permissions, затем переименовывается поверх исходного. Permissions старого файла не копируются; журнал сохраняет только байты и существование. Правка исполняемого `.sh`/`.command` может убрать executable bit, а восстановление через журнал его не вернёт.

**Исправлять:** определить поддерживаемые метаданные файла, сохранять их при замене и восстановлении. Проверка равенства байтов недостаточна для обещания корректного изменения файлов проекта.

### 20. P3 — все ошибки API возвращают HTTP 400

**Установлено по коду.** Источник: [src/api.rs:39](A:/LocalGemmaStudio/src/api.rs:39).

Неверный ввод, отсутствие файла, конфликт занятого чата, ошибка диска и отказ inference возвращаются одним статусом. Клиент не может надёжно различать исправление ввода, повтор позже и внутренний сбой. Это мешает восстановлению отправки и нормальной диагностике.

**Исправлять:** типизированные ошибки и стабильные машинные коды, корректные 4xx/5xx, отдельное сообщение для пользователя и техническая диагностика.

## Порядок исправления общих механизмов

1. **Целостность работы и данных:** владение деревьями процессов; сохранение отправки/частичных результатов; восстановление активной задачи. Критерии: после остановки потомки не пишут; после 503 черновик и вложения доступны; после reload можно увидеть/остановить свою задачу.
2. **Единая модель диалога:** материалы вложений и сообщения как источник контекста; отдельные режим, разрешения инструментов и intent. Критерии: URL, retry и смена модели не теряют материалы; объяснение с явной просьбой читать/исправлять получает нужные возможности.
3. **Жизненный цикл моделей и установки:** состояния загрузки, конечная проверка, отмена, сброс назначения, разделение инвентаря и запуска процессов; транзакционное обновление. Критерии: оборванный download никогда не зелёный успех; смена диска после отказа не требует правки JSON.
4. **Восстановление и общие операции:** schema/revisions, повреждённые файлы, отмена всех worker, permissions, поздние результаты, per-chat locks. Проверять не только happy path, но и занятый файл, закрытый клиент, concurrent requests.
5. **Законченность функций:** возобновляемая задача агента, критерии проверки проекта, большой документ, управление материалами/данными, честный перечень реально работающих возможностей модели. Новые продуктовые возможности выбирать отдельно от исправления уже воспроизведённых дефектов.

Для этого проекта основной приоритет — согласованность состояния и восстановление сценариев. Добавление ещё одной модели, инструкции в prompt или частного исключения под фразу не исправит эти механизмы.

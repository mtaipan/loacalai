# Реализация объединённого плана

Начата 1 ноября 2026 по команде пользователя. Ветка: `codex/product-overhaul`.
Объём остаётся полным: DEVELOPMENT-PLAN.md, PRODUCT-REVIEW, фронтенд, поиск, агент и новые требования R01–R15. Этот журнал фиксирует выполненное; отсутствие пункта здесь не означает его отмену.

## Выполненные механизмы

- R09 / AUD-01: срок задачи и число действий отключены по умолчанию (0). Миграция прежних обязательных значений; явные пользовательские квоты продолжают работать. У HTTP-клиента больше нет общего 10-минутного обрыва тела ответа; подключение ограничено отдельно. Подтверждения ждут решения или отмены без собственного срока.
- AUD-01: дерево команды принадлежит Windows Job Object с запретом breakaway и уничтожением при закрытии. Процесс создаётся приостановленным и запускается только после назначения в job. На Unix используется отдельная группа процессов. Завершение родителя не освобождает потомков от отмены/срока; закрытие владельца освобождает группу.
- AUD-07: ошибка следующей порции перевода сохраняет уже полученный текст.
- AUD-14: повреждённые настройки не заменяются молча значениями по умолчанию; ошибка сообщает путь исходного файла.

## Проверено

`cargo test --locked --offline`: 51 пройден, 1 пропущен (реальный системный буфер обмена). Новые проверки: отмена и срок после выхода родителя с живым потомком; успешная команда без срока и оба потока вывода; долгое ожидание подтверждения с последующей отменой; отключённые и явные квоты. Фикстуры используют временные каталоги, без пользовательского проекта и инференса.

## Границы

macOS/Unix дерево процессов пока проверено по коду; физическая macOS, GPU и реальные модели не проверены. Возврат накопленного вывода при прерывании команды, управление постоянными серверами, долговечный журнал задач, восстановление соединения, права и остальные пункты плана ещё в работе. Не считать текущий этап завершением всего плана.

## Сохранение и восстановление задач

- AUD-02/03/09, GAP-04, R13: SQLite WAL с устойчивыми записями запросов и событий. HTTP-подписчик больше не владеет выполнением. GET `/api/runs`, `/api/runs/{id}`, `/api/runs/{id}/events?after=N`; постраничное чтение событий, последовательность и защита от повторной отправки с тем же request_id.
- При перезапуске активные записи становятся interrupted. Накопленные события доступны; команды и изменения не повторяются автоматически. Миграция чатов JSON пока не выполнялась; Task/requirements/steps ещё предстоит связать с журналом Run.
- Черновик и вложения очищаются после start принятого запроса. Защита двойной отправки действует ещё до создания чата. Перезагрузка открывает подписку на активную задачу и восстанавливает остановку.
- AUD-16: переименование и удаление удерживают блокировку регистрации запусков до окончания изменения, закрывая гонку проверки занятости.
- Проверки: `cargo test --locked --offline` — 52 пройдены, 1 пропущен. `scripts/tests/test_task_lifecycle.py` — реальный HTTP disconnect/replay/idempotency и Edge reload/stop/saved answer пройдены. Дополнительная браузерная инъекция HTTP 503 сохранила текст и вложение; двойное нажатие создало один чат.
- Журнал SQLite использует bundled rusqlite; обращения выполняются через spawn_blocking, чтобы файловые транзакции не блокировали Tokio executor. Основание API: https://docs.rs/rusqlite/latest/rusqlite/struct.Connection.html.

## Контекст и выбор поведения

- AUD-04/05/06/08: составной запрос «объясни ошибку и исправь» сохраняет инструменты; URL не выключает предыдущую историю; извлечённый материал сохраняется у исходного сообщения и восстанавливается при retry/смене модели. Для старых чатов используется извлечение из существующих карточек, без повторного OCR.
- Чат с поиском сохраняет свои пользовательские инструкции и температуру. Возможность вызывать инструменты больше не определяет параметры генерации. Нулевое число действий не превращается в промпте в лимит 1.
- LEG-01: смешанная просьба о ревью и исправлении на разных краях вставленного исходника не уходит в ветку анализа без действий. Имена функций исходника не считаются командами.
- `scripts/tests/test_context.py`: пройдены новые проверки URL/history, Chat persona/sampling, mixed intent и retry материалов; сохранены проверки больших требований во всех режимах, истории, multilingual/thinking, неполного tool call, output limit, настроек и Edge/mobile. Повторные аудитные фикстуры подтвердили перенос материала при retry и сохранение истории после URL; частичный перевод сохраняется при ошибке второй порции.

## Разрешения

- R01/R04, GAP-03: режим подтверждения действий, автоматическая запись в проекте, полный доступ. Полный доступ не даёт дополнительных прав ОС; в UI прямо указаны последствия. В режиме проекта удаление/перемещение, команды, сайт и микрофон сохраняют запрос подтверждения.
- Однократное разрешение; создание/изменение файлов внутри канонического проекта до завершения Run либо до отзыва; точная команда с канонической папкой для Run/проекта. Папка команды не объявляется sandbox. Записи снаружи проекта не получают широкое разрешение на его основании. Командные префиксы и шаблоны shell не выводятся автоматически.
- Сохранённые разрешения видны и отзываются в настройках. Разрешения Run снимаются по завершении и не переносятся через рестарт. Повреждённый файл разрешений не игнорируется.
- Карточки подтверждения и инструментов сохраняют DOM при неизменном содержимом: поток не сбрасывает select/focus/details. При ошибке API кнопки подтверждения становятся доступны вновь.
- Пройдены проверки прав: сопоставление проекта/задачи/точной команды, запись за пределами проекта, сохранение/загрузка/отзыв, отсутствие переноса временного grant. Edge: один task grant разрешил две настоящие записи файлов в фикстуре, сохранил выбор и фокус во время stream, удалился после завершения.

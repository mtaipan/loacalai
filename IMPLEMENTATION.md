## Разрешения

- R01/R04, GAP-03: режим подтверждения действий, автоматическая запись в проекте, полный доступ. Полный доступ не даёт дополнительных прав ОС; в UI прямо указаны последствия. В режиме проекта удаление/перемещение, команды, сайт и микрофон сохраняют запрос подтверждения.
- Однократное разрешение; создание/изменение файлов внутри канонического проекта до завершения Run либо до отзыва; точная команда с канонической папкой для Run/проекта. Папка команды не объявляется sandbox. Записи снаружи проекта не получают широкое разрешение на его основании. Командные префиксы и шаблоны shell не выводятся автоматически.
- Сохранённые разрешения видны и отзываются в настройках. Разрешения Run снимаются по завершении и не переносятся через рестарт. Повреждённый файл разрешений не игнорируется.
- Карточки подтверждения и инструментов сохраняют DOM при неизменном содержимом: поток не сбрасывает select/focus/details. При ошибке API кнопки подтверждения становятся доступны вновь.
- Пройдены проверки прав: сопоставление проекта/задачи/точной команды, запись за пределами проекта, сохранение/загрузка/отзыв, отсутствие переноса временного grant. Edge: один task grant разрешил две настоящие записи файлов в фикстуре, сохранил выбор и фокус во время stream, удалился после завершения.

## Модели и ресурсы

- R10/R13: одна общая очередь инференса для всех хранилищ. Ожидание очереди отменяемо. По умолчанию запрос передаёт keep_alive=0: после каждого инференса модель освобождается; это консервативный выбор с ценой повторной загрузки между шагами. После прерывания Lease удерживает очередь до отдельного подтверждённого unload. Ошибка очистки блокирует следующий инференс и видна в вычислениях; повторный запуск частного движка действительно перезапускает его, внешний сервер не перезапускается.
- Владение деревом процессов распространено на основной и дополнительные частные движки, включая отмену во время старта. Обычное завершение приложения закрывает job/group и освобождает runner-потомков.
- В диагностике: доступная/общая RAM, занятая подкачка, оценка KV-кэша и ресурсов выбранного окна. Для CPU с достаточными метаданными Auto ограничивается физической оценкой; ручное окно не уменьшается молча. Текущий запрос сохраняется при отказе в размещении. Это приблизительная оценка f16 KV для обычного attention, не гарантия размещения, не полный анализ MoE/hybrid/VRAM. Неизвестные метаданные отмечаются как неизвестные.
- AUD-10/11/12/13: подтверждение terminal success и присутствия установленной модели после загрузки; EOF без успеха — ошибка. Убрано общее 2-часовое ограничение HTTP-загрузки. Папку неустановленной модели можно переназначить после ошибки. Статус читает живые серверы или локальные manifests/blobs без запуска холодного хранилища; неполные blobs не считаются установленной моделью. Повреждённая карта расположений не игнорируется.
- Метаданные модели отменяемы в агентном пути; HTTP /show имеет отдельный срок сетевой операции. Медиаоперация связана с shutdown приложения.
- Проверки: 57 unit-тестов пройдены, 1 clipboard пропущен. HTTP/Edge: отмена инициирует unload, следующий инференс ждёт его, пиковая конкуренция в фикстуре равна 1. Storage fixture: passive status, EOF, повтор с другой папкой, изоляция двух дисков, удаление и запрет переноса установленного. Физические модели и реальное освобождение RAM/VRAM в этом этапе не измерялись.
- Основания протокола: https://github.com/ollama/ollama/blob/main/docs/api.md (keep_alive/unload); https://docs.rs/sysinfo/latest/sysinfo/struct.System.html (измерение памяти).


## Фронт, восстановление и контракты настроек

- Одна подписка на события рабочего пространства вместо отдельного SSE каждого чата. POST /api/runs подтверждает приём независимо от потока, возвращает состояние повторно отправленного запроса; снимок /api/session согласован с курсором журнала. Фоновые запуски продолжаются при навигации между чатами.
- Черновики текста и вложений хранятся отдельно для каждого чата. Ошибки отправки не очищают их. Повтор неопределённой отправки использует тот же идентификатор; перезагрузка восстанавливает активные запуски и управление ими.
- Стабильные карточки инструментов, подтверждений и блоков кода сохраняют выбор, выделение и фокус при потоке и завершении. Отрисовка адаптируется к стоимости обновления. Это ещё не пагинация неограниченного журнала: работа с длительной историей остаётся отдельным этапом.
- Настройки разделены по разделам, несохранённые изменения сохраняются до явного сброса. Сохранение отправляет снимок; ввод во время запроса остаётся в форме. Ревизия настроек предотвращает перезапись чужих изменений (409). Числовые поля принимают тот же диапазон и точность, что сервер; срок показывается в секундах без округления. Определение оборудования не блокирует сохранение остальных разделов.
- Доступные подписи, управление вкладками клавиатурой, фокус и inert для мобильного меню, видимый footer настроек при ширине 320 px. Горячие клавиши учитывают диалоги, меню и поля ввода. Полная проверка экранным диктором и физическая macOS ещё не выполнены.
- AUD-21: HTML ответа мог содержать id/classes/data-атрибуты управления приложением. Разметка модели/Markdown теперь ограничена содержимым; управляющие атрибуты и элементы удаляются. Кнопки приложения создаются отдельно после очистки. Предпросмотр обычного исходника использует textContent. Проверено реальной браузерной инъекцией, включая поток и завершение.
- Копирование сообщает успех только по подтверждению API/fallback; восстановление фокуса и выделения выполняется и при ошибке. Тесты используют подмену clipboard, не меняют системный буфер пользователя. Индикатор локальности учитывает адрес сервера инференса. Удалена часть пустых слоганов; общая редактура всех поверхностей ещё в работе.
- Проверки: cargo test --locked --offline — 57 пройдены, 1 clipboard пропущен; release build. scripts/tests/test_task_lifecycle.py — disconnect/replay/idempotency, Edge reload/stop, права и фокус, черновики/вложения, навигация с фоновой задачей, поздний ввод настроек, HTML-границы, последовательный unload. scripts/tests/test_context.py — весь прогон с дробными температурами/штрафом, нестандартными целыми резервами и сроком 61 с, конфликт ревизий, Edge/mobile. scripts/tests/test_specialist_protocols.py — весь прогон протоколов специалистов, браузера и больших источников. Использованы изолированные данные и подставной инференс; качество настоящих моделей этим не проверено.


## Завершение прав и удаление журнала

- Смена политики разрешений и выдача многоразового grant применяются к уже ожидающим действиям. Регистрация ожидания и пересмотр используют одинаковый порядок блокировок; окно между проверкой политики и регистрацией закрыто. Политика проекта не подтверждает команды/удаления автоматически. Отзыв не отменяет уже выполненные действия.
- Запуск остаётся активным до дописывания/закрытия его журнала. При отказе диска отправляется отмена, приёмник дожидается окончания производителя событий; удаление/смена ресурсов не обгоняют работающий код.
- Удаление чата транзакционно удаляет inputs/runs/events и сохраняет tombstone ID. JSON удаляется после фиксации намерения; повторный запуск завершает удаление после сбоя. Чтение/запись/новый запуск не восстанавливают удалённый чат. Миграция журнала до schema 2 не изменяет содержимое существующих чатов. Это логическое удаление, не заявление о криминалистическом стирании страниц SQLite/WAL/резервных копий; общая политика хранения ещё в работе.
- cargo test --locked --offline: 59 пройдены, 1 clipboard пропущен. Новые проверки: выборочное разрешение ожидающих действий и восстановление удаления с сохранением постороннего чата. Полный test_task_lifecycle.py повторно пройден, добавлена HTTP-проверка удаления JSON, run inputs и событий. Release build прошёл.

## Долговечная цель и рабочий план

- R13/GAP-01/02: отдельная Task с замороженной папкой, исходной целью, журналом пользовательских запросов/вложений и планом; несколько Run относятся к одной Task. Непустые содержательные реплики чата также попадают в журнал цели, чтобы смена режима не выбрасывала уточнения. Короткие приветствия не создают рабочую цель. Schema 3 транзакционно переносит принятые запросы старого журнала, не повторяет действия и не меняет исходные JSON-диалоги.
- read_task читает индекс запросов, полный исходный текст по частям и текущий план со ссылкой на Run. update_plan сохраняет состояние между попытками. «Продолжай работу» начинает с чтения сохранённой Task. Краткий паспорт цели находится вне обрезаемой истории; полный текст не подменяется этим отрывком. Убрана квота восемь шагов плана.
- UI показывает цели и запросы, позволяет начать новую или выбрать прежнюю для следующего сообщения. Выбор сохраняется в черновике и виден над вводом. Новая/выбранная рабочая задача использует режим агента/команды. Рабочий контекст помечен Task ID и не смешивает разные цели одного чата. Изменившаяся папка не подменяет молча проект продолжаемой задачи.

## Журналы и управляемые процессы

- R09/R10/R12/R13: saved events теперь содержат ссылку, а не весь чат со всей историей. Фоновое завершение не загружает диалог в браузер. Завершение видимого Run загружает канонический чат с проверкой владельца; старый ответ/повторное подтверждение не очищают следующий поток. Старые saved events поддерживаются при чтении; существующие дубли ещё не удалены миграцией, чтобы не уничтожить возможный источник восстановления.
- Вложения проверяются до принятия нового Run; отсутствие файла не очищает черновик и не создаёт принятую пустую задачу. Идемпотентное чтение уже принятого запроса не требует повторного наличия вложения.
- run_command и новые start_process/poll_process/write_stdin/stop_process используют общий владелец process group/job и отдельные stdout/stderr файлы. Убрано отсечение command logs на 250 КБ; большие журналы не накапливаются в RAM. API читает их страницами по байтовому смещению, исходные байты можно скачать потоком. Скачивание фиксирует накопленную длину на начало запроса, а не ждёт будущий вывод бесконечно. Отмена/срок сохраняют частичный вывод; перед конечным состоянием журналы синхронизируются, ошибки сохранения видны.
- start_process возвращает управляемую сессию, которая живёт после успешного ответа в той же Task. Следующий Run читает её через read_task и продолжает работу. Запуск процесса не означает готовность сервера; readiness нужно проверять по реальному ответу/выводу. Процесс прекращается по отмене создавшего его Run или shutdown; фатально завершившийся Run дожидается остановки созданных им процессов. Отдельная задача не может управлять чужой сессией через эти инструменты. Это ограничение приложения, не OS sandbox.
- stdin — точный текст с отдельным подтверждением для агента; пользователь может отправить его через явную кнопку инспектора. Псевдотерминал не реализован: TTY-only программы остаются неподдержанными. UI показывает реальный status/exit code, часть вывода, загрузку исходных потоков и остановку. HTML процесса показывается буквальным текстом. Удаление чата с живыми процессами блокируется с указанием, где их остановить.
- После рестарта старый PID не используется для автоматического kill/replay: состояние помечается interrupted. Повреждённые записи остаются на месте и видны в диагностике, не блокируя запуск остальных функций. Логи завершённых запусков и резервные копии пока имеют отдельный жизненный цикл; общая политика хранения/очистки ещё в работе.
- Общая проверка структуры аргументов до default/approval/effects: типы, обязательные/неизвестные поля, enum, диапазоны и вложенные объекты. Отрицательные/дробные сроки и offsets не превращаются в defaults. Непредставимый системными часами срок возвращает ошибку вместо panic.

Реальные команды: 1,1 МБ stdout без потери, stderr, stdin, отмена после частичного вывода, восстановление повреждённой записи и старого состояния. test_process_lifecycle.py: агент/HTTP/Edge, процесс переживает Run, UI и следующий Run отправляют stdin, чужая Task отвергается, model failure дожидается cleanup, raw download, inspector 320 px. ## Потоковая подготовка целых материалов

- R09/R10/R13, schema 6: общий ingest_text и инструмент ingest_file создают неизменяемый UTF-8 источник, не собирая весь файл в String. Временное тело и прогресс декодирования фиксируются транзакционно по страницам. Отмена сохраняет байтовый offset/кодировку/ревизию; новый Run той же Task продолжает префикс. После рестарта SHA пересчитывается по сохранённым кускам с ограниченной памятью, затем обработка продолжается с нужного байта. Неполный источник не публикуется как готовый артефакт; при следующем запуске прерванные операции видны.
- Готовый материал получает SHA-256 декодированного текста и дедуплицируется. BOM/размер исходника/кодировка хранятся в provenance; этот хеш не выдаётся за хеш исходных UTF-16/legacy байтов. Повтор внутри Task использует готовую ссылку; другая Task получает собственную ссылку при явно разрешённой подготовке, даже если тело одинаковое. Общий GC учитывает также незавершённые ingests: удаление другого чата не уничтожает их префиксы. Повреждённые metadata не заменяются молча на пустые.
- Scope named-file применяется к ingest_file так же, как к read_file. read_task и task API показывают незавершённую подготовку, её offset/error и имеют курсор страниц. В UI — прогресс подготовки и ссылка «Исходный материал», открывающая именно текст, а не JSON результата. Готовность подготовки не равна прочтению/анализу моделью; это явно отражено в контракте инструмента. Обычные текстовые вложения пока используют прежний preprocess: автоматическое подключение нового источника ко всем типам материалов — следующий этап, не объявлен готовым.

## Политика веб-инструментов: external / loopback / disabled

- Egress разделён явно: external разрешает поиск и наблюдавшиеся web URLs с прежней private-origin проверкой; loopback выключает web_search и разрешает только точный явно указанный пользователем localhost/loopback origin (scheme/host/port); disabled для материалов и перевода отключает web tools. Scope отдельно сохраняет read-only Chat/Search. UI называет off «Только localhost» и уточняет независимый сетевой доступ команд; материалы не показываются как «Авто».
- Политика применяется до извлечения вложений/инференса, включая Results без LLM и material-only запрос. При смене политики закрывается owned worker/browser со всеми открытыми соединениями, при новой логической Task сбрасывается прежняя browser authority. Перевод закрывает существующий browser при необходимости, но не занимает новый browser slot. Обычный HTTP fetch больше не выдается за текущую страницу живого браузера.
- Worker проверяет HTTP navigation/subresources/fetch и WebSocket; старый Playwright без websocket routing не запускается с обходом guard. Запрещённый WS не подключается к серверу; закрытие отложено до выхода из callback: воспроизведён deadlock installed sync adapter при close внутри callback, подтвержден traceback и устранён.
- Воспроизведён обход guard при native browser redirect: route callback не вызывается для каждого hop. Теперь каждый HTTP resource получает только первый ответ через NoRedirect; redirect возвращается с redirect_to/302 и требует отдельного открытия/проверки origin. Перенаправленные subresources блокируются, partial rendering раскрывается через blocked_requests. Контент другого origin не подставляется в исходный origin. Недоступный redirect/ошибка browser-internal page не выдаются за прочитанный источник; после abort проблемная страница заменяется чистой, refs сбрасываются. HTTP status хранится по Page и сохраняется при browser_read, включая 404.
- Вместо unbounded route.fetch body используется bounded raw transfer: Content-Length до чтения, потоковые блоки, 8 MiB буфер одного ресурса, проверка короткого тела, отсутствие автоповторов POST. Это предел отдельного буфера, не квота запросов/страниц/времени Task. Превышение явно сообщает resource_buffer_exceeded; task progress сохраняется. loopback fetch/resource pinning соединяет localhost только с ::1/127.0.0.1, сохраняя Host/TLS SNI и обычную проверку сертификата. Redirect не следует автоматически и для fetch_url. Blocked diagnostic lists bounded; переполнение pending blocked WS закрывает browser с сообщением, не весь Task.

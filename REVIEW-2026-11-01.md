# Local Gemma Studio: ревью 1 ноября 2026

Проверена архитектура основных подсистем и связанные сценарии отказов. Это обзор кода и перечисленные ниже прогоны, а не доказательство отсутствия других ошибок и не построчная экспертиза каждой зависимости.

## Приоритетные оставшиеся замечания

### P1 — отмена команды не гарантирует остановку дочерних процессов

`src/tools.rs:216–269`, функция `capture`: на Windows при отмене живого родителя вызывается `taskkill /T`, а на Unix — только `child.kill()`. Если родитель завершился, но потомок держит stdout/stderr, тайм-аут ожидания потоков лишь прерывает чтение. На macOS потомки могут продолжить изменения после сообщения об остановке; отдельная ветка с уже завершившимся родителем затрагивает и Windows. Это вывод по коду, воспроизведение на macOS не проводилось.

Следующий шаг: группы процессов на Unix, Job Object на Windows, единый финализатор для отмены, тайм-аута и закрытия приложения; тест с потомком, который пишет контрольный файл после отмены. Не считать отмену доказательством отката выполненных команд.

### P2 — обновление установщиком может оставить смешанную версию

`scripts/Setup.cs:40–48`: извлечение пишет файлы непосредственно в целевую установку через `File.Create`; предварительная подготовка отдельной версии и откат не предусмотрены. Ошибка на занятом EXE или другом файле после нескольких успешных записей оставляет часть файлов обновлённой. Сценарий прерывания установки на пользовательской копии не запускался.

Следующий шаг: распаковка во временную папку, проверка полного пакета, завершение приложения в простое, переключение версии и откат при ошибке. Текущий локальный EXE обновляется отдельной процедурой после проверки простоя; это не исправляет сам установщик.

### P2 — проверка заявлений браузерного агента остаётся эвристикой

`src/agent.rs:103–130`, `browser_claim_issue`: проверяются известные формулировки успеха. Связь между независимым подтверждением входа и конкретным действием не моделируется. Возможны пропуск перефразированной выдумки и отклонение настоящего результата, описанного категорично. Тесты подтверждают защиту от известных ложных отчётов после открытия формы, а не универсальную достоверность.

Следующий шаг: типизированный журнал наблюдений, сравнение состояния до/после, проверяемые критерии результата и отдельные уровни «попытка / наблюдение / подтверждение». Модель и текст страницы не должны сами присваивать последнюю категорию.

### P2 — просмотр статуса запускает движки дополнительных хранилищ

`src/model_storage.rs:133–174`: `tags()` обходит все сохранённые каталоги и вызывает `endpoint()`, который при необходимости запускает отдельный Ollama. UI обновляет статус регулярно. При множестве дисков это создаёт дополнительные процессы и последовательные задержки, даже без запуска соответствующей модели. Замер с десятью физическими дисками не проводился.

Следующий шаг: кеш инвентаря моделей, ограниченная параллельность опроса, запуск движка выбранного хранилища по необходимости; отдельно показывать недоступный диск.

### P2 — повреждённые настройки незаметно заменяются значениями по умолчанию

`src/api.rs:212–215`: ошибка чтения или десериализации приводит к `unwrap_or(defaults)` без видимого предупреждения. Аналогичный подход есть у карты расположения моделей. Атомарная запись уменьшает риск повреждения при сохранении, но не помогает при уже повреждённом или вручную изменённом JSON. Следующее сохранение способно затереть прежние настройки значениями по умолчанию.

Следующий шаг: различать отсутствие файла и ошибку, сохранять повреждённый оригинал, показывать восстановление/резервную копию. Не мигрировать пользовательские данные молча.

### P2 — определение запроса на ревью по первой/последней строке неоднозначно

`src/agent.rs:260–264`: если начало просит ревью, а последняя отдельная строка просит исправление, первая строка может всё равно выбрать анализ без инструментов. Нельзя решать эту проблему поиском слова `run` во всём исходнике: так уже ошибочно классифицировались имена функций.

Следующий шаг: явное выделение пользовательской инструкции отдельно от исходника и приоритет просьбы о действии. Дополнительно проверить продолжения ревью: текущая ветка статического анализа очищает рабочую историю, поэтому источник не гарантированно сохраняется для следующей реплики.

### P3 — внутренние ошибки API возвращаются как ошибка запроса

`src/api.rs:32–45`: общий `ApiError` всегда возвращает HTTP 400, включая ошибки диска и недоступность движка. Клиенту трудно отличить неверные настройки от временного отказа сервиса. Нужны отдельные типы ошибок и коды 4xx/5xx, без выдачи успешного статуса при ошибке.

## Исправлено в 0.16.0

| Проблема | Изменение |
|---|---|
| Разные лимиты до запуска противоречили `num_ctx`; инструменты и резерв ответа не учитывались вместе | Общий модуль `src/context.rs`, проверка окончательного payload, настройка окна/Авто/ответа, сохранение расхода движка |
| JSON-экранирование завышало стоимость кириллицы; длинная текущая задача отклонялась общим сообщением | Оценка содержимого без повторного экранирования; текущий запрос сохраняется; реальный предел указывается отдельно |
| История дополнительно обрезалась числом сообщений и байтами | Используется общий бюджет; старые раунды удаляются целиком, обычный чат повторно использует подготовленную историю |
| Большое вложение отклонялось до автоматического разбора на части | Предел суммарной передачи отделён от контекста; размер частей и заметок связан с доступным бюджетом |
| Остановка по длине исчезала после адаптера или оставалась лишь временным уведомлением | Флаг и причина остановки сохраняются; чат явно помечает неполный ответ, инструменты не исполняют незавершённые вызовы, перевод не выдаётся за завершённый |
| Компактор повторно выбирал уже сокращённый ответ и мог терять анализ специалиста | Пропуск уже сокращённых записей; сохранение ограниченного `analysis`, статуса и области проверки |
| Foundation-Sec обходила общие настройки запуска и резерв CPU | Общий механизм inference, контекста, отмены и проверки устройства |
| При сохранении Windows-чата старая запись удалялась до замены | Атомарная замена чатов, настроек и карты моделей; проверен отказ замены при заблокированном файле с сохранением старых байтов |

## Охват

| Подсистема | Проверка и границы |
|---|---|
| HTTP/API и история | Чтение маршрутов, локальная привязка, Host/Origin, токен изменений, валидация, сохранение и ошибки |
| Агент и модели | Управление инструментами, область задачи, подтверждения, отмена, контекст, thinking, адаптеры, команда, проверка завершения |
| Файлы и проекты | Поиск/чтение/изменения, резервные копии, журнал исполнения, сохранение путей и изоляция удаления моделей |
| Браузер/поиск | Реальный Edge на тестовой странице: refs, смена документа, подтверждения, отклонённый вход, границы origin; протокол WebSailor и отсутствие reranker |
| UI | Настройки и сохранение контекста, повторное открытие, ширина 390 px, отсутствие ошибок JavaScript; остальная вёрстка просмотрена по коду |
| Медиа, вычисления, поставка | Просмотр OCR/аудио, путей Python, выбора устройства, пакетов GPU, установщика и macOS-скриптов; физические устройства и macOS не тестировались |

Положительные наблюдения: API слушает локальный интерфейс; изменения защищены токеном и проверками Origin/Host; CSP не разрешает `unsafe-eval`; карточки инструментов используют фактический журнал; запись файлов подтверждается и проверяется по байтам; запрет/тайм-аут не превращаются в успешный статус. Это отдельные свойства, а не общий сертификат безопасности.

## Выполненные проверки

- `cargo test --offline`: 48 пройдено, 1 пропущен (реальный буфер обмена).
- `cargo check --no-default-features --offline`: пройдено на Windows; это не сборка под macOS.
- `cargo clippy --all-targets --offline`: без ошибок, с предупреждениями о стиле и числе аргументов; предупреждения не скрывались флагом подавления.
- `scripts/tests/test_context.py`: банковские требования полностью доходят до тестового inference в Chat/Agent/Team; кириллица и другие языки; резерв thinking; нативный предел; ручной overflow без потери текущего запроса; некорректные настройки не меняют сохранённые данные; остановка по длине, обрыв потока и незавершённые tool calls; настройки в Edge.
- `scripts/tests/test_specialist_protocols.py`: настоящая браузерная форма и подтверждённые действия на локальном fixture, отклонённый вход без ложного успеха, Foundation/WebSailor/команда, большие вложения и вставленный код с полным покрытием исходника по частям.
- `scripts/tests/test_browser_audit.py`: refs, формы, смена документа, origin, отсутствие настоящих секретов в журнале, блокировка заглушек учётных данных.
- `scripts/tests/test_model_storage.py`: разные каталоги, сохранение путей, агрегированные теги, изолированное удаление, запрет опасного переноса.

Интеграционные ответы LLM имитируются. Эти проверки подтверждают работу приложения, а не качество конкретных весов. Банковский проект не создавался и его Testcontainers-тесты не запускались. Полный новый прогон Qwen3-Coder 30B, реальная нехватка RAM/VRAM, CUDA/ROCm/Metal, OCR/микрофон и сборка DMG не проверены. Подсчёт токенов остаётся оценкой; больший контекст увеличивает потребление памяти ([документация Ollama](https://docs.ollama.com/context-length)).

Рекомендуемый порядок следующей работы: гарантированное завершение дерева процессов → безопасное обновление установщиком → восстановление повреждённых настроек → журнал проверяемых результатов агента → ленивые хранилища и уточнение обработки ревью.

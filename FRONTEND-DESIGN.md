# Целевой фронтенд Local Gemma Studio

Статус: проектирование, 1 ноября 2026. Детализация R14/DEC-11 в [едином плане](DEVELOPMENT-PLAN.md). Основания: [аудит UX-01…UX-30](FRONTEND-AUDIT-2026-11-01.md), [исследование](UI-UX-RESEARCH-2026-11-01.md). Ниже определено поведение, а не только визуальный стиль. Реализации ещё нет.

Дополнение R15: [UI-COPY-GUIDE.md](UI-COPY-GUIDE.md) определяет тексты всех состояний и конкретные замены; аудит дополнен UX-31/UX-32. Строки и их соответствие реальному состоянию входят в дизайн/приёмку каждого компонента, а не в необязательную полировку после реализации.

## 1. Информационная архитектура

Основной экран — рабочее пространство с тремя понятными областями:

| Область | Назначение | Поведение |
|---|---|---|
| Левая навигация | Проекты, поиск истории, связанные диалоги/исследования и активные задачи | Компактные группы, статус задачи/ожидания решения, просмотр другого чата без остановки работы; отдельный вход в модели/настройки |
| Центральная область | Разговор, постановка задачи и читаемый результат | Сохраняемый draft/composer, сводка текущей Task, ответ, понятные действия, ошибки с восстановлением |
| Правый inspector | Материалы и результат выбранной задачи | Файл/preview/diff, требования/проверки, источники/фрагменты, процессы/логи. Открывается по явному действию, ширина регулируется |

Без проекта можно начать обычный чат/поиск/перевод. Root для действий агента выбирается явно и виден перед изменением файлов. Переключение проекта не перепривязывает молча уже выполняемый run. «Рабочая папка» в глобальных settings не заменяет принадлежность конкретной Task проекту.

Desktop имеет несколько одновременно видимых областей только при достаточной ширине. В узком окне inspector становится отдельной поверхностью с возвратом; sidebar — overlay drawer с правильной модальностью. Человек не прокручивает весь документ по горизонтали ради Send или закрытия панели.

Основные режимы сохраняются: **Агент / Команда / Чат / Поиск / Перевод**. Они меняют назначение работы, а не одновременно всю навигацию. На широком экране — компактный selector; на малом — одна подписанная кнопка текущего режима и доступный список всех режимов. Quick остаётся отдельным быстрым окном/действием, не шестой вкладкой основного composer.

## 2. Composer и материалы

- Перед вводом понятны текущий mode, scope проекта, модель, сеть и права. Постоянно видны краткие значения; подробные настройки раскрываются по запросу. Не показывать все controls как равнозначные мелкие ссылки.
- У каждого conversation/task/search context свой draft с текстом, attachment IDs и selection/положением при необходимости. Переключение контекста/новый чат/перезагрузка сохраняют draft. Accepted snapshot отделён от нового текста, набранного во время отправки.
- Состояния отправки: editable → validating → submitting → accepted либо recoverable error. Двойной submit использует один request ID. Uploading attachment имеет собственный статус/ошибку/retry/remove; неподдержанный формат объясняется до отправки.
- Во время работы поле ввода остаётся доступным. Основное действие с новым текстом — **«Добавить уточнение»**; приём и применение уточнения видны. Остановка — отдельная подписанная кнопка текущей Task. Enter не вызывает Stop через общий send handler.
- Enter/Shift+Enter, Ctrl/Cmd+Enter и IME имеют единый описанный контракт; выбор поведения отправки можно настроить. Горячие клавиши учитывают overlay, редактируемое поле, композицию и платформу.
- Drag/drop и paste относятся к активной поверхности. Текст+картинка, файл+текст, Unicode/большой фрагмент, native clipboard и permission error имеют сценарии. Глобальный handler не перехватывает ввод в постороннее поле/settings.
- Attachment chip: имя/тип/объём, стадия и результат извлечения, preview по кнопке с клавиатуры, remove/retry; для изображения различаются OCR/vision. Полнота прочтения и scope материала видны до существенного решения.

## 3. Работающая задача и подтверждения

Сводка Task находится рядом с текущим разговором: цель, стадия, последнее полезное действие, состояние ожидания, доступные управляющие действия. Длительность — фактическое время, не имитация прогресса/ETA. Проценты показываются только при известном знаменателе (например, блоки документа), а не по elapsed time.

| Состояние | Что показывать | Управление |
|---|---|---|
| Preparing / prefill | Что подготавливается и что модель ещё не начала вывод | Stop, уточнение; поздние события не меняют чужой экран |
| Working | Понятное имя действия и объект, нужная человеку краткая сводка | Stop, уточнение, открыть подробности; чтение другого чата |
| Waiting user | Что требуется, область/последствие решения и что сохранено | Разрешение подходящей длительности/scope, отказ, продолжение после предоставления данных |
| Waiting resource | Чего не хватает или что выполняется раньше | Отмена ожидания/пауза, ресурсные подробности; задача не потеряна |
| Stopping | Отмена запрошена, какие операции ещё завершаются | Не выдавать «остановлено» до подтверждения; не запускать второй конфликтующий run |
| Completed | Результат, изменённые файлы, актуальные проверки | Открыть/экспортировать, новая задача или обоснованное продолжение |
| Partial / failed / interrupted | Что сделано, что осталось, причина и неизвестные эффекты | Безопасное восстановление/повтор шага/просмотр диагностики; сохранённый partial |

Tool cards переводят внутренние имена в действия («Читает файл», «Запускает тесты»). На первом уровне — объект/статус/существенный результат. JSON, command arguments и raw output доступны в подробностях. Logs, diff и большие outputs открываются в inspector с поиском/ranges/копированием, не распирают ленту.

Approval card сохраняет своё ID и DOM/focus во время stream. Действия R01: once/task/project и настройки полного доступа с явной областью, отказ/отзыв. Для многофайлового changeset — сводка и diff; не серия одинаковых непрозрачных окон. После клика отдельные submitting/resolved/error состояния, не повторно активная кнопка из-за rerender. Не подталкивать к расширению прав через размер/цвет/порядок кнопок.

Уведомление о требуемом решении видно при просмотре другого чата; по переходу возвращается нужная Task и карточка. Ожидание не превращается автоматически в пользовательский отказ.

## 4. Результаты, файлы, поиск и документы

- Ответ, артефакт, исходный материал и evidence различаются. У артефакта есть версия/Task, preview/open/download и при необходимости diff. Итог содержит реальные ссылки на результат и проверки.
- Files inspector: дерево с явной догрузкой, выбранный файл и диапазон/версия, preview, diff, добавить материал/путь. Изменение/restore связано с конфликтами хешей и scopes backend.
- Search: собственная история и четыре глубины; вкладки Ответ/Источники/Ход поиска по SEARCH-DESIGN. Inline citation открывает конкретный прочитанный фрагмент. Ошибка поставщика/blocked/partial/несвежие материалы видимы. Квота общего времени/числа страниц по умолчанию отсутствует.
- Search из Chat/Agent показывает компактный прогресс/цитаты и раскрывается в тот же inspector; углубление создаёт понятную связанную сессию. Поиск не стирает историю и не меняет mode.
- Document workspace: оригинал/извлечённый текст, coverage страниц/блоков, OCR, языки/терминология, перевод с сохранением частей, resume и экспорт. Существующие ограничения страниц/абзацев заменяются потоковым workflow, а не спрятаны новым экраном.
- Редактирование старого сообщения: явный edit/branch с переносом материалов и сохранением старой версии либо честное действие «Использовать как новый запрос». Retry не удаляет предыдущие ответы/артефакты без возможности возврата.
- Preview HTML/кода из модели не исполняется в основном DOM. Если требуется runnable preview, он использует отдельное изолированное окружение с явно определёнными возможностями и origin, не снятие CSP.

## 5. Настройки, модели и первый запуск

Настройки — отдельная адаптивная страница с навигацией и поиском:

1. Общие: язык интерфейса/тема/поведение ввода/доступность.
2. Модели: роли, совместимость/установленность, downloads/jobs, папки и восстановление.
3. Вычисления: устройство, фактическое размещение, memory/context policy и ошибки fallback.
4. Агент и права: инструкции, scopes/grants, default policy, навыки/инструменты при наличии.
5. Поиск и сеть: провайдеры/readiness, источники/даты, ключи и куда идут запросы.
6. Перевод и медиа: модели/языки/терминология, mic/OCR/vision readiness.
7. Системная интеграция: shortcuts, native permissions/clipboard и конкретная диагностика.
8. Данные и восстановление: backup/import/export/cache/retention, состояние миграции.

Сохраняется выбранный раздел и незавершённый ввод. Scope «для этого чата/проекта/всего приложения» виден. Save bar закреплён; dirty/saving/saved/error/conflict различаются. Validation у поля и summary с переходом к ошибке; server rejection не очищает форму. Конфликт настроек между main/Quick/другим окном обрабатывается revision, а не overwrite всей устаревшей формы.

Модельный popover остаётся быстрым: текущее назначение и совместимые варианты. Большой каталог/установка открываются отдельным экраном. Понятны вес загрузки, роль и требования, состояние очереди/скачивания/проверки, отмена/повтор/reset назначения. Не выдавать отсутствие response за готовность и размер GGUF за полное требование RAM.

Первый запуск проверяет нужный сценарий, не заставляет настраивать всё сразу. Можно начать доступную функцию и отложить другие модели. У неготовой функции — конкретная причина и действие («выбрать установленную», «настроить поиск», «разрешить микрофон»). Не запускать скачивание больших весов или внешних компонентов без пользовательского действия.

## 6. Визуальная система и доступность

Сохранить спокойную идентичность продукта: нейтральные поверхности, тёплый акцент и ясная типографика. Это рабочее приложение; декоративный welcome не должен вытеснять первое действие. Статусы имеют текст/иконку, а не один цвет.

| Основа | Проектное правило |
|---|---|
| Типографика | Начальный body/readable answer 16 px, controls около 14 px, metadata обычно 12–13 px; rem и увеличение текста. Это ориентиры дизайна, не нормы WCAG и не запрет крупного пользовательского шрифта |
| Цвета | Семантические surface/text/secondary/border/focus/success/warning/error tokens; обязательный контраст в dark/light, без слабого --subtle для значимых подсказок |
| Размеры/ритм | Последовательная шкала отступов и размеров, достаточные targets; touch-ориентир 44×44 при сохранении AA-критериев и исключений |
| Плотность | В центре важны текст и результат; профессиональные подробности раскрываются. Компактная плотность — опция, не единственный мелкий интерфейс |
| Фокус | Видимый, не перекрыт sticky composer/header; initial/return focus, scopes, keyboard paths для всех widgets |
| Motion | Короткие функциональные переходы с reduced-motion; анимация не блокирует управление и не имитирует прогресс |
| Темы | Dark/light/system, изменение system в реальном времени, main/Quick согласованы; forced colors проверяются отдельно |
| Содержание | Русский интерфейс с согласованными терминами; длинный текст/путь/имя/RTL-материал не ломают controls. Технические имена доступны по раскрытию |

Проверяем WCAG 2.2 AA: contrast, keyboard, name/role/value, error identification/instructions, status messages, text resize/reflow, focus not obscured и target size. Не объявлять полное соответствие по одному автоматическому запуску. NVDA/VoiceOver и настоящий Mac — отдельная приёмка.

## 7. Архитектура реализации фронта

Разделить нынешний app.js по ответственности, сохраняя текущий стек до появления доказанной причины сменить framework. Нужны модули, state contracts и стабильное обновление DOM; сами React/Vue/Tailwind не исправляют UX. Не добавлять Node в пользовательский runtime только ради интерфейса.

- API client: typed success/error, request IDs, reconnect/cursor, cancel и обработка offline.
- Domain stores: tasks/runs/messages/materials/models/settings; authoritative состояния приходят с backend. UI stores: route, selected IDs, panels, drafts, focus/scroll/open и pending interactions.
- Event reducer/selector layer: events относятся к run/session/revision, replay идемпотентен; late responses не меняют новый контекст. No transient global busy как запрет всей навигации.
- Views/components: shell/navigation, composer, task status, message/Markdown, tools/approval, inspector, settings/model jobs, media/Quick; общие primitives dialogs/menus/status/form errors.
- Input/overlay router: одна иерархия Escape/shortcuts/clipboard/drag-drop. У overlay владелец и закрытие; event handlers и timers снимаются при уничтожении владельца.
- Streaming renderer: текст обновляется без пересоздания активных controls; законченные Markdown/code blocks не highlight заново на каждый token. Сохранять scroll anchor, выделение, details open и focus. При чтении старого текста не тянуть человека вниз; есть явное «к новым сообщениям».
- Большие истории/логи: ranges/пагинация/ленивая загрузка с доступной навигацией/поиском и копированием полного материала. Обрезанный UI preview не означает потерю исходного артефакта. Виртуализацию применять только с проверкой browser find, keyboard и assistive technology.
- CSP/DOMPurify/escaping и безопасные ссылки сохраняются. Ошибки рендера одной карточки не уничтожают всю историю/черновик; нужна понятная recovery boundary.

## 8. Матрица экранов и состояний

Для каждой изменённой поверхности описать loading/empty/ready/working/partial/error/offline/reconnecting/disabled-with-reason и внешнее изменение/revision conflict, где применимо. Не создавать фиктивные состояния там, где они не нужны.

Обязательные макеты/fixtures: новый пользователь без моделей; обычный чат; агент со множеством действий; ожидание прав; error+partial; продолжение после рестарта; глубокий поиск; большой документ; models/download failure; settings/validation/conflict; file preview/diff; voice permission/recognition; Quick idle/working/error. Для каждого — desktop и узкий layout, клавиатура и темы.

Проверки дизайна и поведения проводятся внутри единого прохода до завершения соответствующего сценария. Пользовательские наблюдения сохраняются отдельно от экспертных гипотез. Если реальные пользователи/assistive devices недоступны, готовится протокол и явно отмечается непроведённое, а не выдумываются результаты исследования.
